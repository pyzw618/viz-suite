# 信息图设计规则

本文件是 `viz-infographic` 的按需参考。先读布局/风格元数据，再查本文件；不要凭感觉堆卡片。

## 一、先蒸馏，再排版

信息图的失败通常不是 CSS，而是内容没想清楚。

1. **写一句核心主张**：必须能被数据或论证支持，包含对象 + 变化/差异 + 影响。
2. **删掉不服务于主张的内容**：背景介绍、方法细节、致谢放到正文或脚注。
3. **分组**：同级要点放同一层；有先后顺序才用步骤/时间轴；有父子关系才用树/金字塔。
4. **每模块 ≤7 个要点**：超过就合并、删减或拆成第二个模块。
5. **每个数字都有来源**：来源、口径、As-of、单位至少给一个；没有来源就不要放数字。

### 标题与主张

- 标题：短、具体、可被图支持；不要写“关于……的分析”。
- 主张：一句话说“所以呢”；避免“显著提升”这类没有比较对象的空话。
- 副标题：口径、时间范围、单位、样本；不重复标题。

### 文字预算

| 位置 | 建议上限 | 超出处理 |
| :--- | :--- | :--- |
| 标题 | 90 字 | 截断 + warning |
| 核心主张 | 160 字 | 截断 + warning |
| 模块标题 | 60 字 | 截断 + warning |
| 模块正文 | 240 字 | 截断 + warning |
| 要点 | 7 条/模块 | 截断 + warning |
| 来源 | 180 字 | 截断 + warning |

## 二、布局选择矩阵

| 信息关系 | 首选 | 备选 | 不要用 |
| :--- | :--- | :--- | :--- |
| 并列要点 | `list-grid` | `list-row` | 时间轴 |
| 阅读顺序/流程 | `sequence-steps` | `timeline` | 四象限 |
| 时间演进 | `timeline` | `sequence-steps` | 金字塔 |
| 层级/优先级 | `pyramid` | `hierarchy-tree` | 循环 |
| 转化/流失 | `funnel` | `sequence-steps` | 网格 |
| 二维定位 | `quadrant` | `compare-binary` | 漏斗 |
| 方案对比 | `compare-binary` | `list-grid` | 时间轴 |
| 分类体系 | `hierarchy-tree` | `mindmap` | 大数卡 |
| 概念拆解 | `mindmap` | `hierarchy-tree` | 时间轴 |
| 闭环/迭代 | `cycle` | `sequence-steps` | 金字塔 |
| 核心数字 | `stat-cards` | `list-grid` | 漏斗 |

选择顺序：**关系 → 模块数 → 标签长度 → 移动端**。不要为了用某个布局而扭曲内容。

## 三、风格选择

| 场景 | 风格 | 理由 |
| :--- | :--- | :--- |
| 研究简报、年度回顾、深度报道 | `editorial` | 衬线标题 + 纸张质感，可信、编辑感 |
| 董事会摘要、产品一页纸 | `minimal` | 高留白、单一焦点，减少装饰干扰 |
| 数据管线、系统架构、技术复盘 | `technical` | 网格、等宽标签、方角，强调结构 |
| 用户研究、团队复盘、品牌简报 | `warm` | 圆角、柔和色、亲和 |

风格只改视觉令牌，不改信息结构。一个任务内不要混用多种皮肤；多图统一用同一皮肤或明确的章节切换。

## 四、网格、对齐与阶段底框（Zone Containers）

- **阶段底框（Zone Containers）**：对于包含实施阶段、多部门协作或端到端管线的信息图，在 spec 中声明 `zones: [{label, kicker, modules: [0, 1]}]`，渲染器自动在外层生成带有微底色与阶段角标的泳道容器，将离散卡片组织成宏观阶段，彻底消灭孤立卡片漂浮在空白画布上的空洞单薄感。
- 桌面内容最大宽度 1240 px；卡片间距 16–18 px；分组间距 24–32 px。
- 卡片内边距 20–26 px；同一布局内保持一致。
- 网格列数：2–4 列；6 个模块优先 3×2 或 2×3，不要 4+2 留大洞。
- 卡片等高由 Grid `stretch` 保证；正文自动换行，不固定高度 + 隐藏。
- 特殊布局：金字塔/漏斗保持中心对称；四象限保留 x/y 轴；树/导图避免连线穿过文字。
- 移动端：单列，卡片间距 12 px；标题 2–3 行；四象限隐藏角标签，保留轴。

## 五、字体与对比度

- 标题、正文、标签三类字体角色；不要同一页超过 2 个字体家族。
- 正文行高 1.5–1.65；标题行高 1.1–1.3。
- 数字用 tabular-nums；单位字号小于数字。
- 正文对比度 ≥4.5:1；大字号 ≥3:1。
- `muted` 文本在浅色底上容易低于 4.5:1；渲染器会 warning，必要时换更深的值。
- 中文标题避免被拆成“单字孤行”；通过缩短标题或调整宽度解决，不要用负字距硬塞。

## 六、图标

- 只从 `assets/icons/index.json` 选择；按语义（增长、目标、用户、数据、时间）选，不按形状选。
- 图标尺寸 24–42 px；与标题同色或使用焦点色；不填满卡片。
- 图标是辅助，不替代文字；同一模块最多一个图标。
- 禁止 Emoji 充当图标；未知图标回退 `circle-dot` 并 warning。
- 图标不内嵌外部 URL；全部本地 SVG。

## 七、来源与数字

- 有数值必须提供 `source`；缺失时显示「数据来源：未提供」并 warning。
- 来源写法：`数据来源：部门/报告 + 日期 + 口径 + （合成/脱敏）`。
- 脚注写口径、单位、目标定义、缺失/剔除、推演假设。
- 不把相关性写成因果；不编造排名、百分比或增长。
- 百分比要说明分母；百分点与百分比不能混用。

## 八、HTML / SVG 双通道

- HTML：响应式、可访问、适合屏幕与打印；`figure` + `figcaption` + `aria-label`。
- SVG：固定 1200×1600 海报，适合嵌入报告/演示；Python 侧折行与截断。
- 两个通道共用同一份 JSON 与风格令牌；内容与主张必须一致。
- HTML 不依赖外部字体/脚本/图片；SVG 不嵌入外部资源。
- 需要 PNG 时用 `viz-web/capture_html.py --full-page`；不要用低分辨率截图冒充交付。

## 九、验收清单

1. 一图一主张；标题是结论/主题，不是“图表”二字。
2. 单模块 ≤7 要点；文字在预算内。
3. 布局与信息关系匹配；没有错用时间轴/漏斗。
4. 中文折行正确；无单字孤行、无重叠、无裁切。
5. 卡片对齐；网格无大洞；移动端单列可读。
6. 图标全部来自本地库；无 Emoji。
7. 有数值必有来源与口径。
8. HTML lint 0 blocking；`check_layout` 无横向溢出。
9. SVG 文本无溢出；导出尺寸正确。
10. 宿主读图工具目检通过，`visual_verified` 才能为 true。

## 十、常见故障

| 现象 | 原因 | 修复 |
| :--- | :--- | :--- |
| 卡片高度参差 | 不同列内容长度差异大 | Grid stretch + 统一 body 行数/字号 |
| 标题被裁 | 固定高度 + overflow hidden | 缩小字号或截断并 warning |
| 移动端横向滚动 | 固定宽度、长英文串 | `min-width:0`、`overflow-wrap:anywhere` |
| 四象限标签打架 | 点太密、标签太长 | 减少点、短标签、隐藏角标签 |
| 图标不显示 | 图标名不在索引 | 回退 `circle-dot`，warning |
| SVG 文字出界 | 折行估算过宽 | `fit_text` 缩字号/截断 |
| 来源缺失 | JSON 未提供 source | 显示“未提供”并 warning |
| 风格对比度不足 | muted 色太浅 | 换深色或增大字号 |
